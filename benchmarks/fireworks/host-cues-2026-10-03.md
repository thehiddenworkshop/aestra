# F5B — particle-driven host cue delivery, 2026-10-03

The editable multi-break shell exports `launch`, `main_break`, and `secondary_break`
through ordinary particle output routes. A native Bevy host selects its sound identifiers
from real messages. No independent audio timer, actual audio files or playback are used.
This is bounded root-shell integration evidence, not AAA acoustic/artistic acceptance.

## Delivery contract

Native GPU particle records stamp their producing playback epoch into the existing header
padding word; record and ring sizes do not change. Each route retains one `(epoch, tick)`
high-water mark. Records are sorted before delivery, then rejected if stale, duplicate,
out of order or at/before the seek boundary. The runtime preserves a new delivery epoch
when a checkpoint restores old simulation state. Root hosts also reject queued messages
whose `playback_epoch` differs from the current player epoch.

The public message uses `Option<u32>`: native particle routes and timeline cues are qualified;
legacy homing/finished/stage outputs remain `None`, without a freshness guarantee. This
explicit limitation avoids labeling delayed unqualified outputs with the current epoch.

`FirstPerTick` is one representative effect-local position plus source count per route/tick,
not a packet per emitted child. Hosts transform positions and choose spatial voices, pooling,
mixing and sound assets. The native ring stores 32 simulation ticks; `EachEvent` stores at
most 16 positions per tick. A readback stall can lose observations; this is not gameplay
authority or a lossless delivery API.

## Native evidence

RTX 4070 SUPER / Vulkan, dev build, 960×540, high tier, seed `0xf1e0000000000001`,
manual 60 Hz simulation, **playback-only**, semantic materials, HDR/Tony/exposure 0/bloom 0.15.
The initial shell plays uninterrupted; seeking and restart are separate correctness checks,
not the live runtime's default operation or a replay-performance requirement.

`target/fireworks-f5/f5b-host-cues-complete.json` records epochs 1, 2 and 3:

| Run | Launch | Main break | Secondary packets / parent deaths |
| --- | --- | --- | --- |
| Initial forward playback | 1 at tick 1 | 1 at tick 80 | 21 / 64, ticks 153–176 |
| Seek to frame 160, then resume | 0 | 0 | 16 / 55, ticks 161–176 |
| Restart and play forward | 1 at tick 1 | 1 at tick 80 | 21 / 64, ticks 153–176 |

The check compares all remaining seek cues with the original stream, and matches the full
restarted stream's kinds, ticks, counts and representative positions (0.001 tolerance).
Paused reconstruction must emit no qualified particle cues. Runtime tick flooring places
the reconstructed boundary at tick 159 for this f32 seek destination. Queued stale-message
rejection and repeated/out-of-order/stale GPU readbacks also have deterministic unit tests;
this run observed zero stale host messages, not evidence of a deliberately delayed readback.

`target/fireworks-f5/f5b-multi-break-live.json` separately rechecks forward admission:
all four links accept their entire demand **64 / 1 / 48 / 512**, with no source overflow,
expansion omission or destination rejection. Observed trail evictions/truncation are zero;
all 600 simulation samples record zero checkpoint-capture bytes. Estimated effect buffers
remain 2,701,504 bytes (not total device memory), with 716 event readback samples.
Idle-tail percentiles do not certify finale throughput.

## Reproduce

Use fresh output filenames; the cue-check CLI rejects existing paths.

```powershell
cargo test --locked -p aestra-viewer -p aestra-bevy -p aestra-runtime -p aestra-gpu --lib --bins
cargo test --locked -p aestra-bevy-render --lib particle_outputs::tests
$env:AESTRA_REQUIRE_GPU_CONFORMANCE = '1'
cargo test --locked -p aestra-bevy-render --test stateful_conformance -- --test-threads=1
cargo clippy --locked -p aestra-viewer -p aestra-bevy -p aestra-bevy-render -p aestra-runtime -p aestra-gpu --all-targets -- -D warnings
cargo run --locked -p aestra-viewer -- --fireworks-f0 --fireworks-f0-probe f5-multi-break --backend gpu --history playback-only --semantic-materials --camera audience --hdr --fireworks-cue-check target/fireworks-f5/host-cues-new.json

```
